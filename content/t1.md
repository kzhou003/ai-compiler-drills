lede: 同一个 kernel，在 TTIR、TTGIR、LLVM IR、PTX 四层里长什么样？哪些概念在哪一层出现、哪一层消失？这道题写一组读 IR 的小工具，用它们把 vector add 和 matmul 的四层 dump 逐层解剖，找出 layout encoding、layout conversion 和最终的 MMA 指令。

## 背景

roadmap 的 T1：“实现 vector add、row reduction、matmul 三个 kernel；对 matmul dump TTIR、TTGIR、LLVM IR、PTX；标出每个 IR 阶段新增 / 消失的概念；找出 layout encoding 和 conversion；确认 dot 最终映射到哪些 MMA 指令。交付：一个可复现脚本 + IR 注释版。”

本题分两半：

- **读**（本题的测试）：`fixtures/t1/` 里有按真实 Triton 输出格式整理的四层 dump（为了好读做了删减：省略了大部分地址计算，保留了每层的关键结构）。你写的函数要能识别阶段、统计 op、抽出 layout、找出 MMA。
- **dump**（在 GPU 上）：用 `CompiledKernel.asm` 拿到你自己 kernel 的真实四层文本，喂给同一组函数。

:::

**几个要认识的东西**

| 写法 | 在哪层 | 含义 |
|---|---|---|
| `tt.get_program_id x`、`tt.make_range`、`tt.splat`、`tt.addptr` | TTIR / TTGIR | program instance 编号、`tl.arange`、广播、指针算术 |
| `#blocked = #ttg.blocked<{sizePerThread = [...], ...}>` | TTGIR | 线程到元素的映射（T2 会算它） |
| `#mma = #ttg.nvidia_mma<{versionMajor = 2, ...}>` | TTGIR | Ampere Tensor Core 累加器的 layout |
| `#ttg.dot_op<{opIdx = 0, parent = #mma, kWidth = 2}>` | TTGIR | `tl.dot` 的 A（opIdx 0）/ B（opIdx 1）操作数 layout |
| `ttg.local_alloc` / `ttg.async_copy_global_to_local` / `ttg.local_load` | TTGIR | shared memory 缓冲、`cp.async`、从 smem 读进寄存器 |
| `ttg.convert_layout` | TTGIR | 两个 layout 之间搬数据（T2 判断它的代价） |
| `addrspace(3)`、`@llvm.nvvm.read.ptx.sreg.tid.x` | LLVM IR | shared memory 地址空间、`threadIdx.x` |
| `mma.sync.aligned.m16n8k16.row.col.f32.f16.f16.f32` | LLVM IR（asm）/ PTX | 一个 warp 算 16×8×16 的 fp16 MMA，fp32 累加 |
| `ldmatrix.sync.aligned.m8n8.x4[.trans].shared.b16` | PTX | 从 smem 按 MMA 需要的分布读 4 个 8×8 矩阵 |

::: callout analogy 同一份菜谱的四种语言
TTIR 是**菜谱**：“把 A 和 B 搅拌在一起”。TTGIR 是**厨房分工表**：“1 号到 4 号厨师各搅一部分，先把食材从冷库搬到操作台”。LLVM IR 是**每个厨师的操作卡**：“我是 17 号，我搅第 3 行第 8–15 格”。PTX 是**把操作卡翻译成厨房设备的按钮序列**。读 IR 就是对照这四份文件，看哪一句话在哪一份里第一次出现。
:::

## 提示

::: hint 1 一行一个 op
MLIR 的文本形式一行一个 op：`%9 = tt.load %8, %6 : ...` 或 `tt.store ...`。给出的 `_OP` 正则已经处理了左边的 `%x = ` 和多结果 `%res:2 = `，你只需要逐行 `match`，跳过以 `//`、`#`、`}` 开头的行。
:::

::: hint 2 layout 抽取
alias 行的形状固定：`^(#\w+)\s*=\s*#ttg\.(\w+)(?:<\{(.*)\}>)?\s*$`。`parse_attr_body` 用 `(\w+)\s*=\s*(\[[^\]]*\]|#[\w.]+|[^,]+)` 逐个抓键值，列表转成 int 列表。
:::

::: hint 3 convert_layout 和 concept_diff
`ttg.convert_layout %x : tensor<...> -> tensor<...>`：取两个 `tensor<…>`，encoding 是第一个逗号之后的部分（`_encoding_of`）。`concept_diff` 就是对相邻两层的 `concepts()` 集合做差：`sorted(b − a)`、`sorted(a − b)`。
:::

## 在 RTX 3070 上：自己的 dump

```python
import torch, triton, triton.language as tl
from solutions.t1_ir_anatomy import *

@triton.jit
def add_kernel(x, y, out, n, BLOCK: tl.constexpr):
    offs = tl.program_id(0) * BLOCK + tl.arange(0, BLOCK)
    m = offs < n
    tl.store(out + offs, tl.load(x + offs, mask=m) + tl.load(y + offs, mask=m), mask=m)

x = torch.randn(4096, device="cuda"); y = torch.randn_like(x); o = torch.empty_like(x)
k = add_kernel[(4,)](x, y, o, 4096, BLOCK=1024)
st = dump_stages(k)                       # {"ttir": ..., "ttgir": ..., "llir": ..., "ptx": ...}
for a, b, app, gone in concept_diff(list(st.items())):
    print(f"{a} -> {b}: +{app} -{gone}")
print(layout_aliases(st["ttgir"]))
```

对 tutorial 03 的 matmul 做同样的事，把 `ptx_instructions(st["ptx"])["mma"]` 打印出来：在 SM86 上应该看到 `mma.sync.aligned.m16n8k16.row.col.f32.f16.f16.f32`；把 `num_warps`、`BLOCK_SIZE_K` 改一改，数一数 `mma.sync` 的个数怎么变（每个 warp 每个 K 步需要 `(warp 的 M 块 / 16) × (warp 的 N 块 / 8) × (BK / 16)` 条）。想看每个 pass 之后的 IR，设 `MLIR_ENABLE_DUMP=1`；只想把各层文本存成文件，用 `TRITON_KERNEL_DUMP=1 TRITON_DUMP_DIR=./dump`。

::: answer 自测：为什么 vector add 的 TTGIR 里没有 convert_layout，matmul 里却有？
vector add 从头到尾只有一种 layout（`#blocked`，每线程 4 个连续 fp32），load、add、store 都在它上面，不需要转换。matmul 的累加器必须是 Tensor Core 要求的 `#mma` layout，而最后的 `tt.store` 想要合并访存的 `#blocked1`，两者对“哪个线程持有哪个元素”的安排不同，所以在 store 之前要插一个 `ttg.convert_layout %9 : ...#mma -> ...#blocked1`。T2 会告诉你这次转换要不要经过 shared memory。
:::
