lede: Luminal 的搜索空间是一个 e-graph：所有等价程序同时存在，改写只增不删。这道题从零写一个 e-graph（hashcons、union-find、congruence rebuild、e-matching、equality saturation、带预算的停止、基于代价的 extraction），用 (a+b)+c、a+(b+c)、b+a 手算验证，再看 Luminal 为什么只对整数开放交换律。

## 背景

roadmap 的 L2：“用 (a+b)+c、a+(b+c)、a+b、b+a 画 e-class；讨论浮点下哪些 rewrite 不一定安全。交付：e-graph 草图 + 一个 egglog 小实验。”

Luminal 的规则写在 egglog 里：核心规则在 [[luminal:src/egglog_core/egglog_preamble.egg|egglog_preamble.egg]]，每个 primitive 自己的规则在 `src/logical/op/<op>/*.egg`。例如 [[luminal:src/logical/op/add/rewrite.egg|add/rewrite.egg]] 开头就是一段值得背下来的注释：

```text
; Encoding bits are observable. Float operand permutation can change a NaN
; payload, so unqualified floating commutativity is not a bit-exact equality.
; Retain the law for exact integer encodings only (fail closed on unknown dtype).
(rule ((= ?out (LogicalAdd ?lhs ?rhs)) (= (dtype-of ?out) (Int)))
 ((union ?out (LogicalAdd ?rhs ?lhs)))
 :ruleset main_ruleset :name "add/rewrite: commutativity, Int")
```

连 `a + b → b + a` 都只对整数开放——更不用说结合律。

| 部件 | 做什么 |
|---|---|
| **hashcons** | 规范化后的 e-node → e-class；同一个 `("+", c1, c2)` 只存一份 |
| **union-find** | `find(c)` 给出代表元；`union` 合并两个类 |
| **rebuild** | 合并之后，子节点的代表元变了，原本不同的 e-node 可能变得相同（`f(a)` 和 `f(b)` 在 `a = b` 之后），要把它们所在的类也合并（congruence） |
| **e-matching** | 在某个类里找所有能匹配模式 `("+", ("+", "?x", "?y"), "?z")` 的替换 |
| **saturation** | 每轮：先收集所有规则的所有匹配，再统一 instantiate + union，然后 rebuild；一轮下来类数和节点数都没变 → 饱和 |
| **budget** | `iter_limit`、`node_limit`：没饱和也要停（`"iter_limit"` / `"node_limit"`） |
| **extraction** | 自底向上求每个类的最小代价（要迭代到不动点，因为类可以有环：`x·1 = x`） |

::: callout analogy 族谱和同名的人
e-class 像“同一个人的所有称呼”：张三、老张、张经理都指向同一个人（union-find 记住“谁是谁”）。hashcons 保证“张经理的儿子”这个称呼只登记一次。rebuild 处理连锁反应：一旦发现“老张”和“张经理”是同一个人，那“老张的儿子”和“张经理的儿子”也一定是同一个人。extraction 就是在所有称呼里挑最短的那个写进正式文件。
:::

## 浮点下哪些 rewrite 不安全

| 规则 | 实数上 | 浮点上 |
|---|---|---|
| `a + b → b + a` | 成立 | 数值上成立，但 NaN 的 payload 可能不同 → Luminal 只对整数开放 |
| `(a + b) + c → a + (b + c)` | 成立 | **不成立**：`(1e8 + −1e8) + 1 = 1`，`1e8 + (−1e8 + 1) = 0`（测试 `test_reassociation_is_not_bit_exact`） |
| `x · 1 → x`、`x + 0 → x` | 成立 | `−0.0 + 0.0 = +0.0`，所以 `x + 0 → x` 对 `x = −0.0` 改变了符号位 |
| `exp2(log2(x)) → x` | x > 0 时成立 | x ≤ 0 时左边是 NaN，右边不是 |
| `a·b + a·c → a·(b + c)` | 成立 | 舍入次数不同；也可能溢出 / 不溢出 |

| 方法 | 要点 |
|---|---|

| `extract(cid, cost)` | `(最小代价, 项)`；`cost(op, child_costs)` |

## 提示

::: hint 1 先过 congruence 测试
`union` 之后不要立刻修 hashcons；全部 union 完再调一次 `rebuild()`。rebuild 的循环：把每个类的 e-node 集合重新 `canon`；用一个新字典 `enode → 类`，遇到已经属于另一个类的同一个 e-node 就 `union`，并记下“这一轮有变化”。
:::

::: hint 2 一轮饱和的顺序
先对所有规则、所有类收集匹配（`matches`），再统一 `instantiate` + `union`，最后 `rebuild`。边匹配边修改会让同一轮的结果依赖遍历顺序。停止条件：这一轮 `unions == 0` 且类数、节点数都和这一轮开始时一样。
:::

::: hint 3 extraction 的不动点
`best = {}`；反复扫描所有类的所有 e-node：子类都已有代价时，算出这个 e-node 的代价，比当前更小就更新、并标记 changed。没有变化时停止。最后从根类开始，按 `best` 里记下的 e-node 递归构造项。
:::

## egglog 小实验（roadmap 的交付物）

仓库里的 [examples/l2_egglog_experiment.py](examples/l2_egglog_experiment.py) 用 egglog 的 Python 绑定做同一件事：声明 `Num` 类型和 `+`，注册交换律、结合律，`run(10)`，再 `check(eq(left).to(right))`。

```bash
.venv/bin/pip install egglog && .venv/bin/python examples/l2_egglog_experiment.py
# equal after saturation
# Num.var("a") + Num.var("b") + Num.var("c")
# 4 iterations
```

4 轮之后饱和，和你自己的 e-graph 的 `history` 长度一样。接着试两件事：(1) 把项数加到 6，观察 egglog 的运行时间和你的 `num_nodes()` 是否同样按 3ⁿ 增长；(2) 仿照 Luminal 的 `add/rewrite.egg`，给规则加一个条件（只在 dtype 是整数时触发），体会“fail closed”。

::: answer 自测：既然浮点结合律不成立，Luminal 怎么发现 split-K 之类需要重排归约的优化？
不靠一条通用的“浮点结合律”规则，而是：(1) 把归约本身做成带语义的节点（`ReduceSum`、`UnspecifiedOrderScanSum`——名字里就写着“求值顺序未指定”），让“顺序可以变”成为这个 op 的契约，而不是任意 `Add` 链的性质；(2) 由用户在图里显式写出精度（matmul 不自动 cast）；(3) 用 L5 那样的 Reference vs device 对拍，在容差内验证结果。规则的合法性在图的语义层面保证，而不是对所有浮点表达式开放。
:::
